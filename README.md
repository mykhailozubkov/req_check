# Storylens

Приложение для BA: проверка user story на неоднозначности, пробелы в бизнес-правилах и противоречия, улучшенная версия и список изменений.

## Запуск

Требуется Node.js 22.13+.

```sh
npm run install:ci
npm run dev
```

Откройте локальный адрес из терминала. В «Подключение Claude» укажите собственный Anthropic API-ключ и модель с поддержкой Structured Outputs (по умолчанию `claude-sonnet-4-6`). Платные запросы выполняются только по нажатию «Проверить стори» или «Учесть ответы». Ключ хранится в памяти вкладки, передаётся серверу по запросу и оттуда только на фиксированный `https://api.anthropic.com/v1/messages`. В исходниках и файлах ключа нет. Приложение не сохраняет ключи, стори или результаты в БД, файлы, localStorage или журналы. Перезагрузка очищает рабочую сессию. Хранение данных у Anthropic регулируется условиями вашего API-аккаунта.

Без ключа доступен явно обозначенный подготовленный демо-разбор WKSP-ORDS-3. Он не выдаётся за ответ модели и не подставляется при ошибке AI-запроса.

## Политика проверки

- Фокус на бизнес-логике: роли, права, данные, ограничения, расчёты, статусы, условия и результат фичи.
- Стандартное поведение UI подразумевается. Отсутствие описания кликов, раскрытия групп, фокуса, прокрутки и типовых состояний интерфейса не считается дефектом стори.
- UI рассматривается, если явно отличается от стандартного либо элементу нужна конкретная информация, влияющая на бизнес-поведение.
- Условия оцениваются по всему документу; требование из Description не обязательно повторять в Given/When/Then.
- Цитаты проверяются точным сопоставлением с исходником. Для противоречия нужны две разные цитаты. Это подтверждает наличие цитат, а не истинность вывода модели.
- Нулевое количество замечаний допустимо. Важность и необходимость внешнего контекста обозначаются отдельно.
- Переписывание сохраняет исходный язык и явно заданные правила. Нерешённые вопросы отмечаются `[BA DECISION REQUIRED: ...]`.
- Ответы BA используются при повторной проверке и сохраняются между проверками в рамках вкладки; изменение исходной стори или контекста сбрасывает накопленные решения.

Политика и JSON Schema находятся в `lib/review.mjs`. Обработчик не исполняет инструкции из стори, не использует инструменты модели и не допускает пользовательский URL провайдера. Результаты отображаются текстом через React, без исполнения HTML.

## Возможности MVP

- Вставка текста, загрузка `.md`/`.txt`, бизнес-контекст, язык ревью RU/EN.
- Ревью с фильтрацией и переходом от цитаты к выделению в исходном тексте.
- Вопросы BA и повторный AI-анализ с учётом ответов.
- Улучшенный Markdown, маркеры решений, журнал изменений и открытые вопросы.
- Копирование и экспорт Markdown; предупреждение об устаревшем результате.
- Ограничения ввода, размера запросов, времени ожидания; защита same-origin; ответы `no-store`.

## Проверки

```sh
node --test tests/review.test.mjs
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

Автоматические тесты подменяют внешний API: проверяют контракт запроса, цитаты, валидацию, отсутствие ключа, ошибки и лимиты. Они не измеряют качество живой модели. После подключения реального ключа нужно оценить ложные замечания, пропуски и сохранение бизнес-смысла на согласованном наборе стори.

Приватный доступ размещённой версии обеспечивает Sites. Локальный dev-сервер предназначен для разработки; не публикуйте его напрямую в интернет без контроля доступа. Стек: React, TypeScript, Vinext/Vite, серверный route handler, Cloudflare Workers/Sites. AI вызывается через Messages API без дополнительных SDK.

Документация провайдера: https://platform.claude.com/docs/en/build-with-claude/structured-outputs
