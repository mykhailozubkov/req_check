# Storylens

Приложение для BA: проверка user story на неоднозначности, пробелы в бизнес-правилах и противоречия, улучшенная версия и список изменений.

## Запуск

Требуется Node.js 22.13+.

```sh
npm run install:ci
npm run dev
```

Откройте локальный адрес из терминала. Анализ использует бесплатный маршрут OpenRouter `openrouter/free`; пользователям не нужно вводить личный ключ. Ключ приложения хранится в Cloudflare Worker Secret `OPENROUTER_API_KEY` и не отправляется в браузер. Для локальной разработки можно задать этот ключ в игнорируемом `.dev.vars`. Реальные запросы выполняются только по нажатию «Проверить стори» или «Учесть ответы».

Модель выбирает сервер. Клиент не может передать другой ключ, платную модель или URL провайдера. Запрос требует JSON Schema и ограничивает цену входных и выходных токенов нулём. Платного fallback нет. Результат содержит фактическое имя выбранной модели. Бесплатная доступность и квоты зависят от OpenRouter; превышение лимита возвращается как ошибка с предложением повторить позже. В Worker настроено ограничение 5 проверок за 60 секунд на IP в пределах локации Cloudflare.

Стори, контекст и ответы BA передаются OpenRouter и провайдеру выбранной модели. Условия обработки данных определяются ими и настройками аккаунта OpenRouter. Приложение не сохраняет документы в БД, файлы, localStorage или журналы. Перезагрузка очищает рабочую сессию.

Подготовленный демо-разбор WKSP-ORDS-3 доступен независимо от AI-подключения. Он явно обозначен, не выдаётся за ответ модели и не подставляется при ошибке AI-запроса.

## Политика проверки

- Фокус на бизнес-логике: роли, права, данные, ограничения, расчёты, статусы, условия и результат фичи.
- Стандартное поведение UI подразумевается. Отсутствие описания кликов, раскрытия групп, фокуса, прокрутки и типовых состояний интерфейса не считается дефектом стори.
- UI рассматривается, если явно отличается от стандартного либо элементу нужна конкретная информация, влияющая на бизнес-поведение.
- Условия оцениваются по всему документу; требование из Description не обязательно повторять в Given/When/Then.
- Цитаты проверяются точным сопоставлением с исходником. Для противоречия нужны две разные цитаты. Это подтверждает наличие цитат, а не истинность вывода модели.
- Нулевое количество замечаний допустимо. Важность и необходимость внешнего контекста обозначаются отдельно.
- Переписывание сохраняет исходный язык и явно заданные правила. Нерешённые вопросы отмечаются `[BA DECISION REQUIRED: ...]`.
- Ответы BA используются при повторной проверке и сохраняются между проверками в рамках вкладки; изменение исходной стори или контекста сбрасывает накопленные решения.

Политика и JSON Schema находятся в `lib/review.mjs`. Обработчик не исполняет инструкции из стори, не использует инструменты модели и не допускает пользовательский URL провайдера. Результаты отображаются текстом через React, без исполнения HTML.

## Возможности MVP

- Вставка текста, загрузка `.md`/`.txt`, бизнес-контекст, язык ревью RU/EN.
- Ревью с фильтрацией и переходом от цитаты к выделению в исходном тексте.
- Вопросы BA и повторный AI-анализ с учётом ответов.
- Улучшенный Markdown, маркеры решений, журнал изменений и открытые вопросы.
- Копирование и экспорт Markdown; предупреждение об устаревшем результате.
- Ограничения ввода, размера запросов, времени ожидания; защита same-origin; ответы `no-store`.

## Проверки

```sh
node --test tests/review.test.mjs
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

Автоматические тесты подменяют внешний API: проверяют бесплатную маршрутизацию, серверный ключ, запрет подмены модели, цитаты, валидацию, ошибки и лимиты. Они не измеряют качество живой модели. Для этого используется согласованный набор стори с BA-разметкой.

Размещённая версия общедоступна: https://req-check.mykhailo-zubkov.workers.dev. Личный API-ключ и вход не требуются. Настройки Cloudflare Access в аккаунте не изменяются. Стек: React, TypeScript, Vinext/Vite, Cloudflare Workers, OpenRouter Chat Completions API. D1 пока не используется, документы остаются в рамках сессии.

Прямой деплой: `npm run deploy:dry-run`, затем `npm run deploy`. Порядок публикации и последующее подключение D1 описаны в [DEPLOYMENT.md](DEPLOYMENT.md).

Версия с личным Claude сохранена отдельно: [BACKUPS.md](BACKUPS.md).

Документация провайдера: https://openrouter.ai/docs/guides/routing/routers/free-router
